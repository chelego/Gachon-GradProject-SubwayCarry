# UtilityJourney_AI

승객이 고정 Waypoint 배열 없이 시설과 주변 사람을 관찰하고, 유틸리티 점수로 지하철 이용 전 과정을 수행하는 독립 Prototype이다.

## 실행

- Scene: `UtilityJourney_AI.unity`
- 재생성 메뉴: `SubwayCarry > Prototype > Build Utility Journey AI Scene`
- 실제 Scene에서는 열차 탑승 후 목적지역 도착까지 `60초` 동안 운행한다.

## A-B 전체 노선 양방향 다중 승객 테스트

- Scene: `BidirectionalTrainLoop_AI.unity`
- 재생성 메뉴: `SubwayCarry > Prototype > Build Bidirectional Train Loop AI Scene`
- 이 Scene에는 `A→B 4명`, `B→A 4명`을 생성한다. 승객은 서로 다른 시간에 1~4번 출구로 들어오며 목적지역 밖으로 나간 뒤 다시 새 사이클을 시작한다.
- 큰 한 화면에 A역과 B역의 대합실, 동일 크기 상·하행 플랫폼, 두 선로를 함께 표시한다.
- 대합실과 플랫폼은 새 단순 도형으로 다시 만들지 않고 기존 `UtilityJourney_AI.unity`의 `MAP 1A`와 `MAP 2A` 외형을 각각 복제한다.
- 기존 대합실의 1~4번 출구 계단은 역사 경계 바깥 배치를 유지한다.
- 월드 공간의 안내 글자는 모두 제거하고 왼쪽 위 열차 운행 상태 UI만 유지한다.
- 하행 열차는 하단 선로에서 `A -> B`, 상행 열차는 상단 선로에서 `B -> A`로만 움직인다.
- 역에 도착하면 `2초` 뒤 승강장 방향 문이 열리고, 완전히 열린 상태를 `10초` 유지한 뒤 닫힌다. 문이 완전히 닫힌 뒤 `2초`가 지나면 출발한다.
- 상행 열차는 위쪽 플랫폼 방향 문 4개만, 하행 열차는 아래쪽 플랫폼 방향 문 4개만 작동한다.
- A-B 구간은 `30초`에 걸쳐 이동한다.
- 종점 정차 뒤에는 진행 방향의 화면 밖으로 열차 전체가 완전히 빠져나간 다음 1초 동안 숨기고, 반대편 화면 밖에서 출발역으로 재진입한다. 같은 선로에서 역주행하지 않는다.
- 열차 외형은 `Prototype_AI.unity`의 `Train Car 1`을 복제하고, 원본에 포함된 승객과 플랫폼 오브젝트를 제거한 뒤 선로 중심에 맞춘다.
- A→B 승객은 A역 하행 플랫폼을, B→A 승객은 B역 상행 플랫폼을 사용한다. 각자 외부 1~4번 계단, 개찰구, 좌·우 계단과 플랫폼 대기 행동을 유틸리티 점수로 선택한다.
- 하행 열차 문이 열린 경우에만 실제 문 통과점을 지나 탑승하며, 열차 안에서는 기존 객차의 좌석·손잡이·기대기·입석 후보 중 성격에 맞는 행동을 고른다.
- 교통카드를 태그하기 전에는 개찰구의 주황색 문 패널이 물리 충돌과 길찾기 장애물로 통로를 막는다. 선택한 개찰구만 열리고 닫힌다.
- 승·하차 중에는 해당 열차의 출발을 잠시 보류하고 NPC 충돌을 해제해, 열차 외부에 걸린 채 끌려가는 대신 문 안쪽 안전 지점까지 확실히 통과시킨다.
- 탑승 시작 순간부터 승객은 열차 이동량을 함께 따라가며, 객차 안에서는 물리 충돌체 대신 Utility AI의 개인 공간·양보·줄서기 계산으로 서로 간격을 유지한다. 목적지역 플랫폼의 안전 지점까지 완전히 나온 뒤에만 물리 충돌을 다시 켠다.
- 객차 내부는 외부 역사의 `NavigationObstacle`을 검사하는 A* 대신 `문 -> 중앙 통로 -> 선택 행동 지점` 전용 경로를 사용한다. 열차가 역 벽을 지날 때 외부 벽 때문에 객차 경로가 실패하거나 반복 재계산되지 않는다.
- 열차 이동량은 승객 위치뿐 아니라 승객이 따라가던 객차 내부 경로에도 동일하게 더한다. 열차가 출발해도 좌석·손잡이·입석 지점으로 향하는 경로가 출발역에 남지 않는다.
- 탑승 직후에는 문 안쪽 `0.85` 이내의 행동 지점을 제외해 최소한 객차 안쪽으로 이동한 뒤 좌석·기대기·입석 행동을 선택한다.
- 목적지역 문이 열리면 모든 탑승 승객이 즉시 하차 목표를 다시 선택하며, 하차가 끝날 때까지 열차 정차를 최대 `18초` 추가로 보장한다.
- 목적지역 도착 후 문이 열리면 객차 안쪽에서 플랫폼으로 걸어 나온 뒤 계단, 출구 개찰구, 무작위 선호 외부 출구까지 이동하면 한 사이클이 끝난다.
- 열차 상태는 `BidirectionalTrainLoopPrototype`이 제공하고, 승객 판단은 기존 `UtilityJourneyDecisionModel`과 `UtilityPassengerBrainPrototype`을 그대로 사용한다. A*는 선택된 시설까지의 이동만 담당한다.

## 흐름

```text
4개 외부 계단 중 무작위 위치에서 시작
-> 현재 위치, 거리, 혼잡, 대기시간을 비교해 입장 개찰구 선택
-> 교통카드 태그
-> 태그한 바로 그 개찰구 문이 열리고 같은 통로로 통과한 뒤 닫힘
-> 목적 노선 방향에 맞는 좌/우 승강장 계단 중 하나를 선택
-> 스크린도어 줄, 의자, 뒤쪽 벽 중 성격에 맞는 대기 위치 선택
-> Prototype_AI Train Car 1 외형의 열차가 선로로 진입
-> 열차 도착과 문 열림을 확인한 뒤 같은 문으로 탑승
-> Prototype_AI의 Train Car 1을 복제한 객차에서 위치 선택
-> 객차 배경만 흔들리며 60초 운행
-> 목적지역 하차
-> 가까운 사용 가능한 계단 선택
-> 출구 개찰구 태그
-> 4개 외부 출구 중 이번 승객의 선호 출구로 이동
-> 잠시 뒤 출발역 외부의 다른 무작위 계단에서 새 사이클 시작
```

## 도면 기준 구조

- 역사 내부는 사용자 도면의 비율과 위치 관계를 그대로 사용한다.
- 1번/2번 출구 계단은 왼쪽 위/아래, 4번/3번 출구 계단은 오른쪽 위/아래에 배치한다.
- 플랫폼 연결 계단은 역사 중앙의 위쪽 2개, 아래쪽 2개로 구성한다.
- 계단은 입구에서만 들어갈 수 있고 양옆과 끝을 얇은 벽으로 막는다. 입구로 진입한 뒤 계단 방향으로 이동하며 전체 동선의 마지막 20%에서만 화면이 어두워진다.
- 계단 시설의 실제 도착 판정은 시각 중심점의 기본 `0.38`이 아니라 입구 충돌벽 앞에서 닿을 수 있는 `0.78`을 사용한다. NPC 몸이 벽에 막힌 채 같은 계단 목표를 계속 미는 상태를 방지한다.
- 계단은 일반 시설의 `0.22초` 상호작용 대기를 적용하지 않는다. 가장 먼저 입구에 도착한 승객이 즉시 계단 통과를 시작하고 뒤 승객은 사용권이 풀리거나 다른 계단을 선택한다.
- 플랫폼 벽 대기점은 중앙 계단 범위 밖의 `-13, -10, 10, 13` 위치에만 배치한다. 기존 Scene에 남아 있는 중앙 `-4, 4` 대기점도 런타임 후보에서 제외한다.
- 개찰구는 중앙 왼쪽과 오른쪽에 각각 세로 1열씩 두고, 각 열은 검은 하우징 6개와 통과구 5개로 구성한다.
- 개찰구 시설 하나마다 독립 문과 앞/중앙/뒤 통과점이 있어 오른쪽 문에 태그하고 왼쪽으로 빠져나갈 수 없다.
- 플랫폼은 `상행 플랫폼 / 상행 선로 / 하행 선로 / 하행 플랫폼`의 동일한 수평 4구역으로 나눈다.
- 플랫폼 계단은 위·아래 플랫폼 중앙에서 좌우 두 갈래로 나뉘며, 각 계단은 개찰구층과 같은 방향으로 바깥쪽을 향해 열린다.
- 하단 플랫폼 의자는 중앙 계단과 겹치지 않도록 좌우에 두 개씩 두고, 가장 바깥쪽에도 한 개씩 배치한다.
- 하행 열차 외형과 객차 내부는 `Prototype_AI.unity`의 `Train Car 1`을 직접 복제해 사용한다.
- 플랫폼 열차를 복제할 때 원본 객차 아래에 함께 들어 있던 `Platform Lower`와 안전선은 제거하고, 객차 본체만 하행 선로 높이에 맞춰 확대한다.
- 스크린도어, 열차 문 애니메이션, NPC 탑승·하차 통과점은 `Train Car 1` 하단의 실제 4개 문 좌표에서 함께 생성한다.
- 도착 시 객차 내부에서 페이드아웃한 뒤 도착 플랫폼을 먼저 페이드인하고, 열차 문이 열린 다음 NPC가 객차 안쪽에서 플랫폼으로 걸어나온다.
- 월드 폭을 넓혀 출구에서 개찰구와 계단까지 실제로 걸어가는 시간이 느껴지게 한다.

## Utility AI와 경로 계산의 역할

- `UtilityJourneyDecisionModel`: 현재 사실과 모든 시설 후보를 비교해 다음 의도와 시설을 선택한다.
- `UtilityPassengerBrainPrototype`: 선택된 시설까지의 실제 이동 비용을 계산하고 판단 결과를 실행한다.
- `GridNavigation2D / A*`: AI가 선택한 의도를 실행하기 위한 보행 경로만 계산한다.
- `UtilityJourneyWorldPrototype`: 개찰구 상태, 열차 도착·문·60초 운행, 화면 전환과 목적지 도착 사실을 제공한다.
- `OverviewUtilityJourneyWorldPrototype`: 승객별로 A→B 또는 B→A 사실을 독립 보관하고, 실제 양방향 열차와 좁은 개찰구·계단·문 통과를 연결한다.

따라서 `개찰구 → 계단 → 플랫폼` 같은 작성된 노드 배열을 재생하지 않는다. 시설이 막히거나 혼잡 비용이 바뀌면 다음 판단에서 다른 개찰구, 계단, 대기 위치 또는 출구를 선택한다.

## 런타임 최적화

- 모든 시설 후보는 먼저 직선거리, 진행 가능 영역, 혼잡도와 Utility 점수만 싼 계산으로 비교한다.
- A*는 후보마다 돌리지 않고 점수가 가장 높은 실제 선택지에만 실행한다. 선택이 유지되는 동안에는 기존 경로를 그대로 재사용한다.
- 경로가 끝났거나 사용할 수 없어진 경우에만 다시 계산하며, 실패 재시도에도 최소 1초 간격을 둔다.
- 플랫폼 대기 중에는 열차 도착·문 상태만 매 FixedUpdate에서 확인하고, 전체 후보 재평가는 약 1.1초 간격으로 제한한다.
- 열차 안에서 운행 중일 때는 목적지역 도착·문 상태만 확인하고 시설 전체를 다시 점수화하지 않는다.
- 디버그 후보 문자열은 실제 Thought UI가 연결된 한 명 테스트에서만 만들며, 8명 전체 화면에서는 생성하지 않는다.
- 왼쪽 위 상태 문자열은 값이 바뀐 경우에만 갱신한다.

## 승객 성격과 유틸리티 조정

- `Profiles` 폴더의 ScriptableObject로 성격별 점수 가중치와 이동 수치를 분리한다. 코드 수정 없이 에셋 값으로 NPC 성격을 추가하거나 조정할 수 있다.
- 실행할 때마다 `QueuePlanner`, `SeatSeeker`, `WallRelaxed`, `Balanced`, `QuickTransfer` 중 하나를 선택한다.
- `QueuePlanner`는 스크린도어 양옆 줄을 선호한다.
- `SeatSeeker`는 열차가 멀면 의자에 앉아 기다리는 것을 선호한다.
- `WallRelaxed`는 뒤쪽 벽에서 편하게 기다리는 것을 선호한다.
- `Balanced`는 거리와 상황을 더 고르게 비교한다.
- `QuickTransfer`는 좌석 편안함보다 문 근처 입석과 빠른 승·하차를 우선한다.
- 각 Profile은 진행도, 거리 효율, 혼잡 회피, 줄 회피, 개인 선호, 결정 유지, 열차 긴급도, 선호 출구, 편안함, 환승 편의 가중치와 걷기·달리기 속도 및 판단 주기를 가진다.
- 열차 도착이 임박하면 모든 성격이 탑승 줄의 가치를 높이고, 문이 열리면 대기 행동을 중단해 열차 문을 다시 선택한다.
- 성격 선호와 작은 실행별 편차를 함께 사용하므로 같은 시설만 반복하지 않되, 방향이 틀리거나 통과할 수 없는 시설을 무작위로 고르지는 않는다.

## 승객 사이의 자율 사회 행동

- 각 Brain이 같은 물리 공간의 다른 승객 위치, 진행 방향, 속도, 현재 선택 시설과 행동을 직접 관찰한다.
- 주변 승객 여러 명의 평균 진행 방향과 평균 속도를 계산해 같은 흐름이면 방향과 보행 속도를 맞춘다. 군중 흐름만으로 완전히 정지하지는 않으며 느린 흐름은 최소 `55%` 속도로 따라간다.
- 현재 위치에서 충돌한 뒤 반응하는 것뿐 아니라 최대 `1.35초` 뒤의 최근접 거리를 예측한다. 경로가 겹칠 것 같으면 한쪽은 약간 감속하고 다른 쪽은 최대 `8%` 가속하면서 미리 옆으로 비킨다.
- 같은 개찰구·계단·열차 문을 선택한 앞사람이 있으면 거리와 순서를 비교해 뒤에서 감속하며 줄을 만든다.
- 같은 방향의 아주 가까운 승객끼리는 서로 앞뒤로 밀어내지 않는다. 뒤 승객만 선두 승객 속도와 간격에 맞추고, 좌우로 겹칠 때만 약한 측면 분리를 적용한다.
- 서로 반대 방향인 승객은 같은 줄로 판단하지 않는다. 줄 추종 속도는 고정된 정지값이 아니라 선두 속도와 현재 간격으로 계산하며 최소 `35%` 이동을 유지한다.
- 반대 방향 사람이 다가오면 개인별 통행 방향 선호에 따라 옆으로 비켜 지나간다.
- 탑승자는 같은 문으로 내리는 승객이 가까우면 먼저 옆으로 비켜 하차를 기다린다.
- 주변 밀도가 낮을 때는 개인 공간을 넓게 유지하고, 사람이 많아질수록 성격의 혼잡 허용도에 따라 간격을 줄인다. 최소 간격 이하에서는 충돌 회피를 계속하지만 불가피한 접촉 상태를 허용한다.
- 실제 주변 인원과 같은 시설을 선택한 인원으로 혼잡도·예상 줄 시간을 매 판단마다 다시 계산한다. 혼잡한 문이나 개찰구보다 덜 붐비는 대안을 고를 수 있다.
- 좌석과 한 사람용 객차 행동 지점은 이미 다른 승객이 사용 중이면 후보에서 제외한다.
- 문 닫힘까지 남은 시간과 자신의 보행 예상 시간을 비교해, 놓칠 위험이 있는 승객만 달린다. 혼잡하거나 하차 승객이 있으면 급해도 감속·양보 판단이 우선될 수 있다.
- 개찰구, 좁은 계단, 열차 문은 물리적으로 한 사람씩 통과하도록 잠금 소유권을 공유하지만, 어느 시설을 고르고 언제 양보할지는 각 승객의 Utility 판단이 결정한다.
- Profile별로 인지 반경, 개인 공간, 혼잡 시 최소 간격, 예의, 적극성, 줄서기 성향, 혼잡 허용도, 통행 방향 선호, 문 닫힘 긴급 기준을 조절한다.

## 화면 표시

- 왼쪽 위 첫 줄: 현재 맵과 열차 상태
- `Personality`: 이번 실행에서 선택된 승객 성격
- `THINKING`: 현재 선택한 행동, 시설과 점수 근거
- `Candidates`: 이번 판단에서 점수가 높은 시설 3개
- `Motion`: 현재 `WALKING`, `RUNNING`, `WAITING` 상태와 실제 속도
- 시설 위치는 Game 화면에 표시하지 않으며 Scene Gizmo를 선택했을 때만 확인할 수 있다.

## 걷기와 달리기

- 기본 이동은 `1.15` 속도의 걷기다.
- 개찰구, 계단, 대기 위치와 출구로 이동할 때는 뛰지 않는다.
- 열차 문이 열린 상태에서 탑승 지점까지 거리가 남았거나, 목적지역에서 문이 열린 뒤 하차해야 할 때만 `2.45` 속도로 달린다.
- 걷기와 달리기 사이에는 가속을 적용해 속도가 즉시 튀지 않는다.

## 현재 범위

- `UtilityJourney_AI.unity`는 집중 확인용 한 명 승객 흐름을 유지한다.
- `BidirectionalTrainLoop_AI.unity`는 양방향 8명과 반복 사이클, 자율 줄서기·거리 조절·좌석 선점을 확인하는 통합 흐름이다.
- 시작역과 목적지역은 같은 역사 맵 Template을 각각 사용한다.
- 이동 판단은 2D 좌표와 시설 의미만 사용하므로 이후 쿼터뷰 투영에서도 같은 Brain을 재사용할 수 있다.
- 현재 최적화는 양방향 8명 통합 Scene 기준이다. 수십 명 이상으로 늘릴 때는 공간 분할 기반 주변 승객 조회와 비동기/분산 경로 계산을 추가한다.
- 실제 시설 고장과 열차 Provider 계약 연결은 다음 단계에서 확장한다.
