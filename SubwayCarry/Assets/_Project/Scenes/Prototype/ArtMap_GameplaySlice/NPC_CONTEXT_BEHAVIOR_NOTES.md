# 상황 기반 승객 행동 수정 — 2026-09-07

## 이번에 확인한 원인

아트 통합용 `SlicePassengerIntent`가 2~7초 대기 후 다시 선택하고, 현재 가까운 후보에 감점을 주며, 시설 3회 방문/체류 만료 뒤 퇴장시키고 있었다. 기존 05의 `UsingActivity`처럼 자리를 유지하지 못했다. 이 통합 어댑터의 차이를 고쳤으며 기존 V2의 Social Steering 전체를 다시 갈아엎지 않았다.

`SlicePathFollower`에는 경로의 앞쪽 지점을 바라보면서도 진행 인덱스를 확정하지 않는 문제가 있었다. 이미 지나친 코너가 다시 목표가 될 수 있어 look-ahead 인덱스를 앞으로 갱신하고 마지막에는 실제 목적지를 사용하도록 수정했다.

## 적용 구조

`목적/장소/시설/군중/이벤트 → Utility 선택 → 행동 유지와 실행 상태 → 기존 Agent/Social Steering/A*`

- 공통 계약: `Ai_v2/Scripts/Runtime/PassengerAiV2PlaceContract.cs`
- 공통 행동 실행: `PassengerAiV2ContextualActivity.cs`
- 독립 조정 자산: `Ai_v2/Profiles/AI_V2_ContextualActivity_Default.asset`
- 현재 아트 맵의 정보 제공자: `SlicePlaceEnvironment.cs`
- 아트/맵 밖 제거/운반물 접촉 연결: `SlicePassengerIntent.cs`

새 코드가 모든 씬에 자동으로 적용되는 것은 아니다. 이번 통합 씬에 연결했으며, 기존 AI 01~06 씬/공유 이동 코드/기본 성격 자산은 보존한다. 05의 좌석 유지 원칙과 예약 계약을 재사용했다.

## 유지와 변경 규칙

1. 통과 목적이면 출구를 한 번 정하고 유지한다. 실패 때마다 반대 출구로 바꾸지 않는다.
2. 대기 목적이면 근처 자리/기대기/입석과 제자리 유지를 평가한다. 제자리도 유효한 행동이다.
3. 자리를 잡으면 보통은 점수를 재계산하지 않는다. 앉거나 기대고 있는데 주변 사람이 지나간다는 이유로 일으키지 않는다.
4. 관련 열차 접근/문 열림 신호가 오면 준비 위치를 선택한다. 객차에서는 목적역 신호에만 반응한다.
5. 무효화된 시설은 다시 선택한다. 입석 상태에서 통행 방해가 지속될 때는 한 번 비킨 뒤 재이동 제한을 둔다.
6. 실제 열차 컨트롤러가 없는 현재 씬에서는 `ReadyForTraversal`에서 기다린다. 닫힌 문을 관통하거나 반대 맵으로 NPC를 순간이동시키지 않는다.
7. 경로 진행이 8초 이상 없으면 실패 지점을 30초 기억한다. 8초 재시도 간격을 두며, 연속 3회 실패하면 방향 변경을 반복하지 않고 환경 변경 신호를 기다린다. 실제 맵 경계/통로가 바뀌면 `NotifyFacilitiesChanged()`도 호출해야 한다.

이 실패 대기는 정상적인 대기와 구분해 HUD `Route waits`에 표시한다. 현재 객차 아트에는 기대기 시설이 등록되지 않아 좌석/입석만 평상시 선택한다. 다른 두 플랫폼에는 등록된 기둥 기대기 위치가 있다.

일반 입석 대기는 문/출구/진입부와 `SliceMap.noWaitingZones`를 피한다. 현재 플랫폼 어댑터는 두 주요 출구 사이의 통행 띠도 제외한다. 이는 현재 맵의 간단한 통행 영역 추정이며 복잡한 역에서는 금지/대기 구역을 명시해야 한다. 문 옆 준비 위치는 일반 대기와 별도다. 실제 승하차 줄/문 상태 제어를 완성했다는 뜻은 아니다.

## 처음 보는 맵에 옮기려면

맵 이름이나 지정 노드 순서를 판단 코드에 추가하지 않는다. 대신 다음 정보를 제공한다.

- 걸을 수 있는 바닥, 벽/기둥 등의 충돌 경계.
- 장소 종류: 일반 공공공간/대합실/플랫폼/객차.
- 좌석/기댈 시설/입석/문 준비 Smart Object의 사용 위치와 수용 인원, 가용 여부.
- 출입구, 대기 금지 구역, 해당 NPC의 목적(통과/대기/탑승 대기/목적역까지 승차).
- 주변 사람의 위치/속도, 관련 열차 및 목적역 상태.

현재 아트 맵은 `SliceMap + SlicePlaceEnvironment`로 이 계약을 제공한다. 다른 내비게이션을 쓰는 맵은 `IPassengerAiV2Place`와 Agent의 이동 공간 연결부를 구현하면 공통 선택/유지 코드를 재사용할 수 있다. **그림만 보고 의자나 역을 스스로 알아보는 시각 인식, 영상 학습, 모든 맵에 대한 완성된 자동 적응은 아니다.** 새로운 맵에서도 실제 군중 테스트가 필요하다. 목적과 관련 서비스의 선택은 상위 여정 시스템이 제공해야 한다.

## 참고한 근거와 확인 범위

- [Field observations and modeling of waiting pedestrian at subway platform, Information Sciences (2019)](https://www.sciencedirect.com/science/article/abs/pii/S0020025519306012): 두 역의 현장 관측/영상 기록을 바탕으로 대기와 통행의 상호작용, 열차 도착과 밀도 변화의 영향을 다룬다. 검색에서 제공된 초록/소개를 확인했으며 논문의 세부 모델을 그대로 구현한 것은 아니다.
- [Understanding Pedestrian Behaviors From Stationary Crowd Groups, CVPR (2015)](https://www.cv-foundation.org/openaccess/content_cvpr_2015/html/Yi_Understanding_Pedestrian_Behaviors_2015_CVPR_paper.html): 정지한 군중도 보행 경로에 영향을 준다는 연구. 공개 초록을 확인했다. 제자리 대기를 별도 행동으로 취급하는 근거로 참고했다.
- [Avalanches of choice, PNAS (2026)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12933032/): 역 분기점의 실측 이동 자료에서 낯선 앞사람을 따라가는 경향을 다룬다. HTML 본문을 확인했다. 이를 모든 상황에서 맹목적으로 따라가라는 규칙으로 확대하지 않았으며 기존의 약한 흐름 반영 이동 코드는 이번에 변경하지 않았다.
- [Tokyo Metro 승차 예절 안내 영상 페이지](https://www.tokyometro.jp/en/tips/mannervideo/index.html): 문 주변에서 통행을 양보하고 차내 안쪽으로 이동하라는 공식 설명을 확인했다. 관측 실험이 아니라 운영기관의 안내/규범이다.
- [서울 지하철 7호선 출근 시간 영상](https://www.youtube.com/watch?v=VJsmW9HD1xQ), [서울역 4→1호선 환승 영상](https://www.youtube.com/watch?v=BpNE_T9P9zg): 참고 후보로 검색했다. 이번 도구에서는 재생 영상/개별 프레임 분석을 완료하지 못했으며 이 영상에서 속도·거리·반응 시간을 직접 측정했다고 주장하지 않는다.

## 최적화와 검증 한계

- 머무르는 Agent는 기존 코드의 hold 상태에서 Social Steering 평가를 건너뛴다. 위치 갱신/최소 상태 확인까지 모두 없어지는 것은 아니다.
- 의미 있는 변경은 이벤트로 알리고, 승객마다 처리 시점을 약간 분산한다. 시설/후보 목록과 HUD의 승객 참조는 캐시한다. 주변 조회에는 기존 공간 해시를 사용한다.
- 경로 계산 한 프레임 2개 제한과 기존 작업 배열 재사용을 유지한다. 제자리 대기로 인해 경로 재요청이 생기지 않는다.
- 결정론 검사에서는 도착 위치/가상 시각을 주입해 600초 유지, 무관 이벤트 무시, 목적역 반응, 예약/시설 소실, 재시도 제한 및 다른 좌표계 경로를 확인한다. 실제 시간으로 10분간 군중을 플레이한 검사가 아니다.
- 사용자가 실제 플레이에서 좌석/입석 유지, 문 앞 대기 금지, 반복 왕복, 군중 속도, 방향 표현을 확인한다. 원격 화면 조작/Play Mode 실행/Profiler 측정은 하지 않는다. 성능 향상률이나 시각적 자연스러움을 수치로 보장하지 않는다.

최종 코드 검사 결과: 결정론 검사 32개 실패 0; 실제 맵 90개 경로(점 이동 수치 계산 포함), 벽 진입 차단 205지점 및 시설 계약 검사 실패 0; Console 오류 0. 원본 791개 파일 해시 비교에서 삭제 없음, 이전 턴의 선택적 Agent 연결부 외 기존 파일 변경 없음.
