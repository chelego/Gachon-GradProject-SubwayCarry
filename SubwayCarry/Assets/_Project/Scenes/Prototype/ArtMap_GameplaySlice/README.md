# 아트 맵 연결 플레이 슬라이스

## 실행할 씬

`ArtMap_01_Gachon_Train_Wangsimni_Playable.unity`

Unity에서 이 씬 하나를 열고 Play. 기존 열려 있는 씬의 수정 사항은 먼저 저장한다.

가천대역 ↔ 객차 ↔ 왕십리역을 연결했다. 세 맵을 나란히 붙이지 않고 현재 맵 하나만 활성화하며, 플레이어는 페이드 전환으로 이동한다. 팀원 원본 씬은 변경하지 않았다.

## 조작

- WASD: 이동. 마우스: 정지 중 바라보는 방향.
- 청록색 타원으로 표시된 문 근처에서 E: 다음 맵. 목적지는 화면 왼쪽 위에 표시된다.
- 역사 문 → 객차. 객차 왼쪽 문 → 가천대역, 오른쪽 문 → 왕십리역. 돌아가는 것도 가능하다.
- 마우스 휠: 확대/축소. 카메라는 플레이어를 따라간다.
- 1 서기 / 2 기대기 / 3 앉기 / 4 지지물 잡기 / 5 머리 위 운반.
- 6~9: 김준 코드의 출발·속도 변화·도착·급정거 균형 입력 시험. 실제 시간표나 열차 운행의 자동 발생은 아니다.
- F6: 관련 열차 접근 / F7: 관련 열차 문 열림 / F8: 출발이라는 **AI 상황 신호만** 보낸다. 문 아트·열차를 움직이거나 NPC를 다음 맵으로 보내는 기능은 아니다.

플레이어와 운반 상자는 청록색 윤곽으로 구분한다. NPC는 같은 캐릭터 아트를 윤곽 없이 사용한다. 왼쪽 위에서 상자/케이크 내구도, 자세, 스태미나, 승객 수와 이탈 수를 확인한다.

## 승객 동작

- 기존 `PassengerAiV2Agent`와 `PassengerAiV2CrowdManager`의 공간 해시, 분산 인식, 사전 회피, 군중 속도 조절 코드를 직접 재사용한다.
- 동일한 `AI_V2_Profile_BasePassenger.asset`을 사용한다. 성격 수치는 임의로 다양화하지 않는다.
- 공통 `PassengerAiV2ContextualActivity`가 목적·장소·거리·주변 밀도·시설 예약으로 걷기/제자리 대기/좌석/기대기 후보를 평가한다. 기존 V2 Smart Object 예약을 사용한다.
- 앉기·기대기·대기는 시간이 지났다는 이유로 해제하지 않는다. 관련 열차 접근/목적역 도착, 시설 사용 불가 같은 의미 있는 변화가 있어야 다시 판단한다. 다른 역 정차/무관한 열차 신호는 좌석 유지를 해제하지 않는다.
- 입석 승객은 지속적으로 통행을 방해할 때만 가까운 빈 공간으로 비킨다. 최소 유지 12초, 연속 방해 4초, 재이동 간격 20초는 초기 조정값이며 실측값이 아니다. 문·출입구·진입부·지정 대기 금지 구역은 일반 입석 대기에서 제외한다.
- 연결된 바닥에서만 A*로 이동하며, 경로 요청은 한 프레임 최대 2개다. 경로 배열과 탐색 작업 배열을 재사용한다.
- 시작 인원은 최대 10명, 전체 상한 18명. 이후 1.5초마다 입구 공간이 비었을 때 추가한다.
- 플랫폼에는 기다리는 승객과 통과하는 승객을 구분한다. 같은 성격 기준으로 목적만 다르다. 대기 인원은 기본 10명까지, 나머지 통과 승객은 한 번 정한 반대쪽 출구로 걸어 나가 제거된다. 객차 승객은 목적역을 기다린다. 수초 단위 랜덤 배회·3회 방문 후 퇴장·좌석 만료는 없앴다.
- 대기 중인 승객을 통행량 유지를 위해 강제로 일으켜 퇴장시키지 않는다. 실제 열차 운행/승하차 연결 전에는 이들이 계속 기다리는 것이 정상이다.
- 맵 전환 시 이전 맵의 군중을 정리하고 새 맵에 군중을 만든다. NPC 한 명의 역간 여정을 유지하는 완성형 시스템은 이번 범위가 아니다.
- 플레이어 위치·실제 이동 속도를 V2 군중에 읽기 전용 참가자로 전달한다. 플레이어를 AI가 조종하지 않는다.
- NPC 접촉 속도는 김준의 `IPackageImpactSource`에 전달한다.

## 원본과 다른 연결용 설정

- 가천대/왕십리 아트 배치와 원본 크기를 유지했다. 객차는 원본이 다른 단위를 사용하여 전체 아트 루트만 0.2배로 정규화했다. 캐릭터 속도/물리 크기는 맵 스케일을 상속하지 않는다.
- 원본 역사 타일은 한 칸보다 큰 바닥 그림을 여러 칸 간격으로 배치한 형태다. 따라서 `HasTile`만으로 걷기 가능 영역을 판단하지 않고, 바닥 스프라이트의 마름모 영역을 합쳐 이동 마스크를 만들었다. 충돌/깊이 기준점은 최초 연결용 근사치이므로 최종 배치는 사용자 시각 확인이 필요하다.
- 기둥/벤치/객차 좌석의 바닥 접촉부에 대각선 다각형 충돌체를 적용했다. 같은 발자국 데이터를 NPC 경로 마스크에도 사용한다.
- 역사 아트는 `y - 0.5*x` 지면 깊이, 객차는 `y` 깊이를 사용한다. 문틀과 좌우 문짝을 하나의 SortingGroup으로 묶어 승객이 문 부품 사이에 그려지지 않도록 했다. 사람의 몸과 운반물도 하나의 그룹으로 정렬한다.
- 닫힌 문/창은 원본 Sprite의 불투명 외곽에서 만든 작은 공유 Mesh로 뒷면을 막았다. 투명한 내부 틈으로 승객이 보이지 않도록 하며 원본 PNG나 임포트 설정은 변경하지 않는다. 실제 문 개폐를 추가할 때는 해당 가림 면과 이동 경계를 문 상태에 함께 연결해야 한다.
- 스크린도어의 실제 하단선과 객차 측면에 이동 경계 및 충돌선을 적용했다. 맵 이동은 문 앞 E 페이드 전환이므로 닫힌 문 자체를 통과할 필요가 없다.
- 사람 아트 Scale은 플레이어/NPC 공통으로 역사 `1.1`, 객차 `0.78`. 기존 역사 NPC `0.68`보다 약 62% 확대했다. 역사 원본 문짝의 대각선 길이를 제외한 유효 높이와 캐릭터 불투명 부분의 키를 비교한 초기 비율이며, 실제감은 사용자 확인 대상이다.
- 충돌 반경은 역사 `0.28`, 객차 `0.23`이며 아트 사각형 전체가 아니라 발 주변에 맞춘다. 바닥 문 표시도 인물/구조물 아래에 정렬한다.
- 잘못된 아트 틈의 작은 고립 공간으로 NPC가 생성되지 않도록 가장 큰 연결 구역에서 등장/목적지 후보를 고른다.
- 전체 배송 경제/정산, 실제 정차 시간표, 열차 문 통과 애니메이션, NPC 전체 역간 여정, 승객의 밀기 물리까지 완성했다는 의미가 아니다. 아트 위의 조작/군중/상호작용 느낌을 보는 연결 프로토타입이다.

## 수정 위치

- 씬의 `ART_MAP_SLICE__Connected_Stations_And_Train` → `SliceGameController`: 최대 인원, 대기 인원 상한, 생성 간격, Seed, Activity Settings.
- `Ai_v2/Profiles/AI_V2_ContextualActivity_Default.asset`: 유지/양보/재시도 시간과 점수 차이 임계값. `AI_V2_Profile_BasePassenger.asset`은 바꾸지 않았다.
- 새 맵 적용 계약과 코드/자료 설명은 `NPC_CONTEXT_BEHAVIOR_NOTES.md`를 참고한다.
- `Map_*`의 `SliceMap`: 출입구, 다음 맵/도착 위치, 시설 위치, 바닥 접촉 영역, 카메라 크기, Character Scale/Radius, Depth Slope, Walls/Solid Footprints.
- `Player_Slice.prefab`: 이 슬라이스용 플레이어 속도/운반 설정. `PlayerController.moveSpeed`와 `SlicePlayerBoundary.moveSpeed`는 같은 값으로 유지한다.
- `Player_CyanOutline.mat`: 윤곽 색/두께.
- Builder는 기존 씬이 있으면 덮어쓰지 않는다. 수동 수정 후 전체 재생성을 실행하지 않는다.
- `SlicePresentationRepair`는 통합 씬의 가림/크기/생성 충돌체만 보정하는 Editor 도구다. 원본 아트 Transform을 유지하며 Play 중이거나 저장되지 않은 씬에는 실행하지 않는다. 수동으로 충돌체를 조정한 뒤에는 다시 실행하지 말고 해당 데이터도 코드에 반영한다.

- 플레이어 프리팹, 8방향 Sprite 8+24개, 프로필, 윤곽 Shader 연결 확인.
